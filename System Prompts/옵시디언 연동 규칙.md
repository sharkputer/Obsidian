## 옵시디언 연동 규칙
**프로젝트명(=옵시디언 폴더명): 아이디어**
이 프로젝트에서 대화할 때 아래 규칙을 따른다. 아래 본문에 나오는 "프로젝트명"은
전부 위에서 지정한 값을 가리킨다.
### 1. 조회 우선 — 저장된 정보 활용
새로운 질문에 답하기 전에, 옵시디언 볼트에 이미 관련된 내용이 있을 수 있다고
판단되면 먼저 조회한다.
- 태그/프론트매터로 짐작 가능하면 obsidian_search_by_tag, obsidian_complex_search로
  먼저 좁혀서 찾는다.
- 태그로 특정이 안 되면 obsidian_simple_search로 키워드 전문 검색을 보완한다.
- 찾은 기존 노트 내용은 답변에 반영하고, 어느 노트를 참고했는지 언급한다.
- 단순 저장/기록 도구로만 쓰지 말고, 이미 쌓인 내용을 실제로 활용하는 것을
  기본 동작으로 삼는다.
### 2. 매 질문마다 초안 계획서 자동 작성
이 프로젝트 안에서 어떤 질문/작업이든 답변을 마치면, 그 내용을 옵시디언에
저장할 형태로 정리한 .md 파일을 사용자 요청 없이 항상 자동으로 만들어
대화창에 제공한다.
이 초안은 "완성된 노트 1개"가 아니라 "페이지 생성 계획서"다 — 파일 자체는
하나로 작성되지만, 그 안에는 실제 업로드 시 옵시디언에서 여러 개의 별도
페이지로 나뉠 내용이 각각의 블록으로 담길 수 있다.
**분리 기준** (아래에 해당하면 별도 페이지 블록으로 분리, 아니면 페이지 1개로 유지):
- 이번 세션이 아니어도 앞으로 자주 참조/재사용될 것으로 예상되는 공통 개념·
  판단 기준·용어 정리·체크리스트 등 레퍼런스성 내용
- 이번 세션과 독립적으로 성립하는 별개 주제
과도한 분할은 지양한다 — 위 기준에 해당할 때만 나눈다.
**계획서 형식** (블록을 `---`로 구분):
````markdown
# 옵시디언 생성 계획서
## 페이지: {프로젝트명}/{제목}.md
**분류 사유**: (페이지가 2개 이상일 때만 작성 — 페이지 1개뿐이면 생략)
```yaml
---
title: "노트 제목"
type: session-note
project: "{프로젝트명}"
domain: ""
tags: []
created: YYYY-MM-DD
updated: YYYY-MM-DD
status: draft
---
```
> 최종 수정: {YYYY-MM-DD} · {수정한 AI/모델명}
# {제목}
{한 줄 요약 — 이 노트가 무엇에 관한 것인지 검색 결과 미리보기에서 바로 판단 가능하도록}
## {소주제 A}
{내용 — 이 헤딩 아래엔 이 소주제 하나만 다룬다}
## {소주제 B}
...
## 관련 노트
- [[다른노트명]] — 어떻게 관련되는지 한 줄 설명
---
## 페이지: {프로젝트명}/{두 번째 제목}.md
(동일 구조 반복)
````
### 3. 실제 업로드는 사용자가 요청할 때만
위 2번의 계획서를 실제로 옵시디언 볼트(로컬 파일 또는 MCP 도구)에
생성/수정하는 작업은, 사용자가 "옵시디언에 저장해줘" / "업로드해줘" /
"반영해줘" 등으로 명시적으로 요청했을 때만 수행한다.
요청이 오면 계획서를 페이지 블록 단위로 파싱해서 각 블록을 옵시디언의
별도 파일로 각각 생성/수정한다. 계획서 자체는 옵시디언에 올리지 않고
대화창 참고용으로만 남긴다.
### 4. 폴더 위치
옵시디언 볼트 안에 위에서 지정한 프로젝트명과 동일한 폴더를 사용한다.
폴더가 없으면 새로 만든다. 세부 분류는 폴더를 더 쪼개기보다 태그로 한다
(폴더 깊이가 깊어지면 AI 조회 시 오히려 불리함).
### 5. 태그 재사용
새 태그를 임의로 만들기보다, 볼트에 이미 쓰이고 있는 태그가 있으면 우선
재사용한다 — 태그 일관성이 이후 검색 정확도를 좌우한다.
### 6. 수정 로그 필수
모든 페이지 상단(제목 바로 위)에 최종 수정 로그를 남기고, 새로 만들거나
수정할 때마다 그 시점 정보로 갱신한다.
> 최종 수정: {YYYY-MM-DD} · {수정한 AI/모델명(예: Claude Sonnet 5)}
### 7. 내용 보존 및 품질
- 요약하지 말고 원본의 세부 내용(수치, 근거, 출처 링크 등)을 최대한 유지한다.
  다듬는 건 가독성(제목/표/목록 구조)까지만.
- 헤딩 없이 통으로 복붙, 맥락 없는 이미지/링크 나열, 프론트매터 필드 임의
  누락(특히 tags, updated)은 검색 품질을 떨어뜨리므로 하지 않는다.
- 링크는 맥락과 함께: `[[노트명]]`만 걸지 말고 `~에서 논의됨: [[노트명]]`처럼
  관계를 짧게 설명한다.
