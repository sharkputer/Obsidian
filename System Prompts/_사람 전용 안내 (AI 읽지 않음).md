# 사람 전용 안내 — AI는 읽지 않음

> ⚠️ 이 문서는 사람이 보는 안내문입니다. "AI 참조 규칙"에 따라 AI는 `_index.md`와 거기서 연결된 파일만 열며, 이 문서는 열지 않습니다.

## 이 폴더는 무엇인가요
여러 Claude 프로젝트에서 재사용하는 시스템 프롬프트를 한 곳에 모아둔 아카이브입니다. 프롬프트 본문을 프로젝트마다 복사하지 않고, 프로젝트 지침에는 이름만 남기고 실제 내용은 여기서 가져다 씁니다.

## 분류 방식 — 폴더보다 태그·링크
깊은 폴더 구조는 AI 에이전트가 훑어보기 어렵고(경로를 다 몰라도 되는 게 장점인데 폴더가 깊으면 그 장점이 사라짐), 노트 하나가 폴더 하나에만 속할 수 있어 유연성도 떨어집니다. 최근 "AI 에이전트 친화적 옵시디언 vault" 관련 자료들도 공통적으로 얕은 폴더 + frontmatter 태그 + 위키링크 조합을 권장합니다. 그래서 이 아카이브는:

- **폴더는 필요해질 때만 대주제 몇 개로 얕게 만듭니다.** 지금은 프롬프트 수가 적어 `System Prompts/` 바로 아래 파일을 두고, 세부 분류 때문에 하위 폴더를 미리 만들지 않습니다.
- **세부 분류·교차 속성은 태그로** 답니다. 프롬프트 파일 맨 위에 이렇게 적습니다.

```yaml
---
tags: [주제, 톤, 용도]
---
```

  하나의 프롬프트가 여러 태그를 가질 수 있어서, 폴더처럼 "이건 이 폴더에 넣을까 저 폴더에 넣을까" 하는 양자택일 고민이 없어집니다. 왼쪽 태그 패널이나 그래프 뷰로 훑어보기도 더 쉽습니다.
- **`_index.md`가 이름·태그·경로·설명을 한 표로 모아 보여주는 MOC(Map of Content) 역할**을 합니다. 사람은 이 표에서 태그로 훑어보고, AI는 이 표에서 정확한 "경로" 열만 사용합니다.

> 태그·위키링크는 사람이 탐색·분류하는 용도이고, AI가 파일을 실제로 열 때는 항상 `_index.md`의 "경로" 열(정확한 상대 경로)을 사용합니다. GitHub 커넥터처럼 Obsidian의 위키링크 해석 규칙을 모르는 경로도 있기 때문에, 태그·링크로 바꿨다고 경로 열을 없애지는 않습니다.

## 폴더 구조 (현재)
```
System Prompts/
├─ _index.md                            ← AI가 참조하는 유일한 진입점 (이름·태그·경로·설명)
├─ _사람 전용 안내 (AI 읽지 않음).md      ← 지금 이 문서
├─ 시스템 프롬프트 작성 규칙.md            ← 메타 프롬프트: 새 프롬프트 작성 형식 + 계획서 선검토 규칙
└─ 옵시디언 연동 규칙.md                  ← 실제 프로젝트용 시스템 프롬프트 1호
```

## 새 시스템 프롬프트가 만들어지는 순서
`시스템 프롬프트 작성 규칙.md`에 따라, 새 프롬프트를 요청하면 AI가 곧바로 옵시디언에 쓰지 않습니다.
1. AI가 파일명·경로, frontmatter, 본문 전체, `_index.md`에 추가될 행까지 담은 **계획서**를 가독성 좋은 문서로 대화창에 먼저 보여줍니다.
2. 사람이 검토하고, 필요하면 수정을 요청합니다.
3. "만들어줘" / "등록해줘" 처럼 명시적으로 승인해야 그때 AI가 실제로 `System Prompts/`에 파일을 만들고 `_index.md`에 등록합니다.

## AI가 실제로 따르는 규칙 (참고용)
프로젝트 지침에 아래 절차가 들어가 있으면, AI는 시스템 프롬프트가 필요할 때 이 순서로 시도합니다.
1. 옵시디언 MCP 연동 → 있으면 그걸로 `_index.md` 읽기
2. 로컬 경로 명시 → MCP 없어도 경로가 있으면 직접 읽기
3. GitHub 저장소(비공개, 커넥터 경유) → 위 둘 다 안 되면 사용
4. 인덱스의 "경로" 열이 가리키는 파일만 열기 (이 안내문 같은 건 열지 않음)
5. 그래도 못 가져오면 왜 실패했는지 사용자에게 알림

## 새 프로젝트에 연결하는 방법
- Cowork·데스크톱(옵시디언 MCP 연결됨): 별도 설정 없이 바로 작동합니다.
- 웹·모바일: Claude 설정 → 커넥터 → GitHub 연결(최초 1회) + 이 저장소 접근 권한 부여가 필요합니다.
- 새 프로젝트의 커스텀 지침 칸에 아래 "지침 문구"를 그대로 붙여넣습니다.

## 새 시스템 프롬프트를 추가하는 방법
자세한 형식·태그·인덱스 등록 규칙, 그리고 계획서 선검토 절차는 `System Prompts/시스템 프롬프트 작성 규칙.md`를 따르세요(이것도 시스템 프롬프트 하나이며 "시스템 프롬포트 제작" 프로젝트에서 항상 적용됩니다).

## 지침 문구 (프로젝트 커스텀 지침에 붙여넣기)
```
## 시스템 프롬프트 참조 규칙
특정 시스템 프롬프트가 필요하면 아래 순서대로 시도한다.
앞 단계로 가능하면 뒤 단계는 시도하지 않는다.
1. 옵시디언 MCP가 연동되어 있으면, 그것으로 System Prompts/_index.md 를 읽는다.
2. MCP가 없어도 로컬 경로가 명시되어 있으면, 그 경로의 System Prompts/_index.md 를 직접 읽는다.
3. 위 두 가지가 모두 불가능하면, GitHub 커넥터로 {GITHUB_OWNER}/{REPO_NAME} 저장소의 System Prompts/_index.md 를 읽는다.
4. 인덱스에서 이름이 일치하는 항목을 찾아 "경로" 열이 가리키는 파일만 읽고, 내용을 이번 작업의 시스템 프롬프트로 삼아 따른다. 인덱스와 거기서 연결된 파일 외의 다른 파일은 열지 않는다.
5. 위 세 가지 방법을 모두 시도했는데도 끝내 가져오지 못했다면, 추측하지 말고 어떤 방법을 시도했으며 왜 실패했는지를 구체적으로 사용자에게 알린다.
```
