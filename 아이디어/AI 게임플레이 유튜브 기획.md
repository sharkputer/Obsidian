# AI 게임플레이 유튜브 기획
사람처럼 화면만 보고 키보드·마우스만 조작하며, 어떤 게임이든 스스로 배워 익힐 수 있는 범용 AI("프로게이머")를 만들고, 사용자("코치")가 실시간 대화로 개입하는 과정을 유튜브에 기록하는 프로젝트의 최상위 기획 문서. 세부 설계는 [[AI 게임플레이 시스템 아키텍처]], 기술 스택은 [[AI 게임플레이 기술 알고리즘 정리]]에 있음.

## 한 줄 정의
사람처럼 화면만 보고(픽셀 입력) 키보드·마우스만 조작(물리적 출력)하면서, 어떤 게임이든 스스로 배워 익힐 수 있는 범용 AI를 만든다. 이 AI는 "프로게이머" 역할이고 사용자는 "코치" 역할로 실시간 대화(텍스트+음성)하며 개입하되, AI는 코치 말을 그대로 따르지 않고 자기 판단에 접목시킨다. 이 전체 과정을 유튜브에 기록해 사람들의 반응을 본다. 목적은 수익화가 아니라 호기심 기반 관찰 실험이다.

## 핵심 원칙 — 절대 바뀌지 않는 두 가지
1. **"사람처럼"**: 게임 내부 상태(메모리, API, 네트워크 패킷)를 절대 직접 읽지 않는다. AI가 가질 수 있는 정보는 화면 픽셀뿐이고, 세상에 영향을 미치는 방법은 키보드/마우스 이벤트뿐이다.
2. **"글로벌 시스템"**: 게임마다 사람이 손으로 새 코드를 짜는 게 아니라, 알고리즘/파이프라인은 모든 게임에서 100% 재사용하고 게임마다 달라지는 건 AI가 스스로 관찰해서 만들어내는 설정값(무엇을 추적할지, 어떻게 조작하는지)뿐이어야 한다.

```
화면 캡처(픽셀) → AI 두뇌(인지·판단) → 키보드/마우스 이벤트(OS 레벨) → 게임 화면 변화 → 다시 캡처
```

## 전체 그림
```
[학습 파이프라인]                         [실전 실행]                        [기록/콘텐츠]
Phase L0 관찰학습                          전략 계층(LLM, 게임 무관)            로깅 → SQLite DB
  (튜토리얼 관찰 또는                        ↕ 코치 채널(텍스트+음성)            웹 대시보드(조작+조회)
   사람 시연 화면+입력 동기화 기록)            ↕ 자발적 질문 ↔ 실시간 매뉴얼 갱신    OBS 녹화 + 하이라이트 자동 클립
  → Phase L1 규칙 압축(매뉴얼 생성)         전술 계층 = 범용 인지 3단계
  → Phase L2 목표 설정                      (추적기 → 제로샷 재탐지 → LLM 폴백)
                                          → 실행 계층(OS 키보드/마우스)
```
이 전체 파이프라인 — 학습 엔진, 전략 계층, 코치 채널, 로깅/대시보드 — 는 모든 게임에서 공통 재사용됩니다. 게임이 바뀌면 실제로 새로 생기는 건 Phase L0~L1이 그 게임을 관찰해서 만들어내는 "매뉴얼"(무엇을 추적할지, 조작 방식, 트리거 규칙) 하나뿐입니다.

## AI 두뇌 구조
### 학습 → 압축 → 목표설정 → 실행 (사람의 운동학습 3단계와 동형)
- **Phase L0(관찰학습, 1회성·고비용)**: 게임 내장 튜토리얼을 보거나, 코치가 직접 플레이하는 화면+실제 입력을 동기화 기록해서 관찰
- **Phase L1(규칙 압축)**: 관찰 내용을 "조작 매핑 + 트리거조건→행동" 짧은 매뉴얼로 압축 — 이게 전술 계층의 초기화 값이 됨
- **Phase L2(목표 설정)**: 매뉴얼 완성 후 이번 판 목표(클리어/점수 등) 결정, 코치가 언제든 갱신 가능
- **Phase E(실전 실행, 저비용·반복)**: 매뉴얼에 있는 건 전술 계층이 LLM 없이 처리, 전략 계층은 매뉴얼에 없는 예외 상황에서만 개입

### 전략-전술 2계층 (반응속도 문제의 해법)
LLM 하나로는 실시간 게임을 감당 못 합니다(짧은 판단도 1~3초, 깊은 판단은 5~15초 — 실측·사례 기반 확인됨, 상세 근거는 [[AI 게임플레이 시스템 아키텍처]] 부록1). 그래서 속도를 둘로 쪼갭니다.
- **전략 계층(느림, LLM)**: 고수준 판단만. 매뉴얼에 없는 예외, 코치 응대, 자발적 질문 담당
- **전술 계층(빠름, 로컬)**: 매뉴얼대로 정확한 타이밍에 실행. 네트워크를 안 타서 우리 코드만 따지면 수 ms, 브라우저 렌더 루프 지터까지 포함해도 체감 5~25ms 수준

### 전술 계층 = 범용 인지 3단계 (게임마다 하드코딩하지 않는 방법)
| 단계 | 방식 | 특징 |
|---|---|---|
| 1단계(매 프레임) | 범용 추적기(KCF/CSRT/MOSSE) | GPU 불필요, 바운딩박스만 주면 색상·모양 무관 추적, 전 게임 공통 코드 |
| 2단계(재탐지, 선택적) | GPU 있으면 제로샷 탐지(YOLO-World), 없으면 생략 | 텍스트 설명만으로 재탐지, 게임별 학습 불필요 |
| 3단계(예외) | 전략 계층(Claude 비전) | 이미 100% 게임 무관, 1·2단계 실패 시 폴백 |

GPU가 없다면 2단계를 생략하고 1단계가 놓치는 즉시 3단계로 직행하는 게 기본 권장입니다 — 재탐지가 드물게만 일어나므로 새 인프라 없이도 충분합니다. 자세한 4단계 대안 비교는 [[AI 게임플레이 시스템 아키텍처]] 참고.

## 프로게이머-코치 상호작용
AI(프로게이머)는 자기 계획/판단을 유지하다가, 코치(텍스트 또는 음성)의 말을 명령이 아니라 참고 정보로 받아들여 상황에 맞게 접목합니다. 강제 우선순위 규칙 없이, 최근 성과 상태를 프롬프트에 실어 보내는 것만으로 "잘 되고 있으면 고수, 안 되고 있으면 더 수용적"인 태도가 자연스럽게 나오게 설계했습니다.

AI도 먼저 질문할 수 있습니다 — 매뉴얼에 없는 예외 상황을 만나면(게임이 허락하는 "안전 지점"에서만) 코치에게 먼저 묻고, 답변은 그 즉시 매뉴얼에 반영됩니다. 이게 "수업 끝나고 몰아서 묻는 게 아니라 필요할 때 물어서 감각과 이해를 계속 연결시키는" 구조의 실제 구현입니다.

음성 채널(VAD+STT로 코치 음성 인식, TTS로 AI 음성 응답)을 더하면 왕복 약 2~4초로 실제 대화처럼 느껴지는 반응속도가 나옵니다.

## 첫 게임: 고군분투
2007년 한게임 플래시로 나온 마우스 클릭 전용 러닝 액션 게임(클릭=점프, 공중 재클릭=와이어). Ruffle 기반 아카이브에서 브라우저로 플레이 가능해 캡처 대상 문제없음. 총 6단계 중 5단계부터 난이도 급상승.

이 게임은 "턴제부터 시작"하는 일반 원칙과 반대로 프레임 단위 타이밍이 핵심이라, Phase 0부터 바로 전략-전술 2계층 하이브리드로 시작합니다. 1~4단계는 전술 계층 정확도만 잡히면 클리어 가능성 있고, 5~6단계는 순수 AI로 넘을 수 있을지 자체가 불확실 — 여기서 막히는 것 자체를 성장담/실패담 콘텐츠로 활용합니다. 경로 분기가 거의 없는 외길 게임이라 AI의 "전략적 판단" 비중은 다른 장르보다 작고, 이후 게임에서 더 온전히 드러날 것으로 예상합니다.

## 게임 확장 로드맵
반응속도 요구치가 낮은 장르 → 높은 장르 순으로, 기술적 이유와 성장 서사가 동시에 맞아떨어지는 순서입니다.

| 단계 | 장르 예시 | 이유 |
|---|---|---|
| 1 | 턴제 퍼즐(2048, 마인스위퍼 등) | 반응속도 무관, 파이프라인 검증 최적 |
| 2 | 포인트&클릭 어드벤처 | 실시간성 낮음, 화면 이해력 테스트 |
| 3 | 여유 있는 캐주얼 액션 | LLM 한계가 드러나기 시작 |
| 4 | 전략/시뮬레이션 | 복잡한 판단력 테스트 |
| 5 | 빠른 액션/온라인 대전 | 순수 LLM 한계 노출 지점 |

(고군분투는 예외적으로 3단계 성격을 1번으로 앞당겨 시작한 케이스입니다.)

## 콘텐츠 포맷 — 한 영상에 겹치는 4개 레이어
- **순수 관전**: 게임 화면 자체
- **성장 스토리**: 에피소드 구조로 시리즈화, 매뉴얼이 두꺼워지는 과정 자체가 서사
- **실패/황당한 행동**: 판단 로그에서 반복 실패·이상 행동 자동 감지 → OBS Replay Buffer로 하이라이트 클립 자동 저장
- **기술 설명 + 코치-AI 대화**: AI reasoning 자막, 그리고 코치가 개입하거나 AI가 먼저 질문하는 음성 대화 자체가 콘텐츠(실제 프로게이머-코치 방송 느낌)

## 인프라 요약
- **로컬 실행**: 게임(브라우저)·캡처·전술 계층·입력 실행·OBS·대시보드는 전부 한 컴퓨터에서 사람처럼 실제 OS 입력으로 동작. 유일한 원격 호출은 전략 계층 LLM과 코치 음성 STT/TTS. 이 컴퓨터의 실제 마우스/키보드를 점유하므로 전용 컴퓨터 한 대로 시작하는 걸 권장
- **데이터/대시보드**: 조작(코치 메시지·세션 제어·매뉴얼 승인)과 조회(로그·세션·매뉴얼·하이라이트)를 웹 페이지 하나로. DB는 SQLite(WAL)로 가볍게 시작하고, SQLModel+Alembic 구조라 필요해지면 PostgreSQL로 연결 문자열만 바꿔 전환 가능
- **GPU 없어도 가능**: 전술 계층 1단계·전략 계층·코치 음성 채널 모두 GPU 불필요. 2단계(제로샷 재탐지)만 GPU가 있으면 좋고, 없으면 그냥 생략하고 전략 계층으로 대체

## 리스크
- **온라인 게임 ToS**: 자동화 프로그램 금지 약관·안티치트 우려 — 초반엔 싱글/로컬/플래시게임 위주로 진행
- **저작권**: 대부분 허용되지만 게임이 늘면 개별 확인 필요
- **지루함**: LLM 판단 지연으로 실시간 화면이 느리게 느껴질 수 있음 — 편집 단계 배속/컷 편집 전제
- **로컬 컴퓨터 점유**: 플레이 중엔 그 컴퓨터로 다른 작업이 어려움 — 전용 컴퓨터 또는 가상 디스플레이로 완화
- **GPU 트레이드오프**: 2단계를 생략하면 재탐지를 전략 계층(LLM)이 더 자주 떠맡아 API 비용/지연이 약간 늘 수 있음 — 실사용하며 재탐지 빈도를 보고 필요시 승격

## MVP 로드맵 (통합 최신판)
1. **L-a**: 코치가 고군분투 1단계를 플레이하는 동안 화면+입력을 동기화 기록하는 로거 구축
2. **L-b**: 기록된 시연을 AI가 매뉴얼로 압축하는지 검증(사람이 품질 검수)
3. **0-a**: 검증된 매뉴얼로 전술 계층(범용 인지 1단계) 구현, 매뉴얼 규칙만으로 1단계 클리어 시도
4. **0-b**: 전략 계층 연결, 예외 상황에서만 개입하는지 검증
5. **0-c**: 코치 인터페이스(텍스트) 연결
6. **0-d**: 음성 채널 연결(VAD+STT+TTS), 자발적 질문 검증
7. **Phase 1**: 코치-AI 대화를 자막/오디오로 얹어 첫 녹화, 대시보드 최소 버전(SQLite+FastAPI) 연결
8. **Phase 2**: 다음 순회 게임 목록 확정, 시리즈 포맷 확정
9. **Phase 3**: 채널 개설, 정기 업로드, 반응 보며 다음 게임 결정

## 다음에 정해야 할 것 (열린 질문 통합)
- 프로게이머 페르소나를 게임마다 다르게 줄지, 하나의 고정 캐릭터로 시리즈 전체를 관통시킬지
- 상태 메모리의 세션 간 장기 기억 유지 여부
- 매뉴얼 구조화 형식(텍스트만 vs JSON 병행), 재학습 트리거 정량 기준
- STT/TTS·2단계 재탐지를 클라우드로 갈지 로컬/생략으로 갈지 — 실사용 비용 보고 결정
- 채널 컨셉/이름, 업로드 주기
